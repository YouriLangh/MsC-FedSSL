## A. Minimal “must-have” metrics that directly support your conclusions

### 1) Pseudo-label utilization (baseline + ADSH)

Even if you didn’t log it originally, you can add it now with a few counters.

Log per round (per client):

- **accept_rate** = (# accepted pseudo-labels) / (# unlabeled samples processed)
    
- **avg_conf_accepted**, **avg_conf_rejected**
    
- **accepted_per_class** histogram
    
- **entropy/prob margin** of accepted pseudo-labels (confidence quality)
    

**Why it helps:**  
It directly supports your claims about “more data used” and “majority-class domination”.

> If ADSH increases accept_rate but accepted_per_class stays skewed → you can claim: “utilization increases but diversity does not”.

### 2) Pseudo-label correctness (only if you can; it’s easy on CIFAR-10)

Since you have labels in CIFAR-10 test/train, you can compute for unlabeled samples:

- **pseudo-label accuracy** = pseudo == true_label (for analysis only)
    
- compute separately for **accepted** and **rejected**
    
- compute per class
    

**Why it helps:**  
It connects pseudo-label utilization to quality. You can show:

- early rounds: many wrong accepted labels or too few accepted labels
    
- minority classes: low pseudo-label correctness / near-zero acceptance
    

This is _the_ cleanest proof that “thresholding doesn’t solve it”.

### 3) Client drift / update disagreement (FedAvg instability evidence)

Log per round:

- **cosine similarity** between each client update Δw_k and global update Δw
    
- or between client updates pairwise (mean pairwise cosine)
    
- **norms** of Δw_k
    

**Why it helps:**  
You don’t need to show logits are “ruined”. Show instead:

> client updates become highly dissimilar under α=0.1 → FedAvg aggregates conflicting directions → instability.

This is a standard and defensible FL measure.

### 4) Calibration / confidence-quality plot (supports “overconfident AUROC vs low F1” story)

You already have AUROC vs F1/recall. Add:

- **ECE (Expected Calibration Error)**
    
- **Reliability diagram** (confidence bins vs accuracy)
    

Compute on test set at several rounds (early/mid/late) for α=0.1 vs α=0.5.

**Why it helps:**  
This directly supports the statement “confidence is not meaningful”, which is the key reason threshold methods fail.

### 5) Representation proxy (cheap)

If you want “representation learning” evidence without deep feature analysis:

- **class-wise test accuracy** and **macro-F1** (macro is crucial under imbalance)
    
- **confusion matrix over rounds** (not just final): show it improves for α=0.5 but stagnates for α=0.1
    
- **mean prediction entropy per class** on test set
    

If you can do one deeper thing:

- **t-SNE/UMAP of penultimate layer features** (global model) for α=0.1 vs α=0.5 at final round  
    (even one seed is fine, labeled test data)
    

**Why it helps:**  
It visually shows “representations entangle similar classes” under α=0.1.
